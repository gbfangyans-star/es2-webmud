# 房間撰寫規範

整理日期：2026-10-27。把散在 `CLAUDE.md` 與各區域文件（`AREA_*.md`、`MAP_RUNTIME_CONTRACT.md`）的房間規則集中在這裡。
寫新區域、新房間前先看這份；規則有變動時回頭更新這份。

---

## 一、設計表的「敘述」是設計需求

使用者交來的房間設計表，「敘述」欄**代表這間房間要具備的設計需求**，不一定是最後要給玩家看的文字。
例如特殊出口、探索指令、機關、要放的 NPC 或物品，都可能寫在這一欄。

處理方式：

| 設計表上的內容 | 做法 |
|---|---|
| 有舊資料可直接當遊戲敘述 | **全文引用**，一字不改，並在列表中標明「舊資料」 |
| 只有設計需求、沒有完整敘述 | 由 Claude 撰寫，標明「新寫」 |
| 舊資料不夠完備（缺環境描寫、缺行數、缺出口提示） | 保留舊資料原文，只補不足的部分，標明「舊資料＋補寫」 |

## 二、製作流程（先列出、確認後才製作）

1. **讀設計表**：整理每間房間的名稱、出口、指令出入、功能（客棧、當鋪、安全區等）、NPC、物品。
2. **對照舊資料**：到 `docs/LEGACY_ROOM_NPC_COMPENDIUM.md` 等舊站資料找有沒有對應房間。
3. **列出敘述清單**：在動手寫程式前，先把每間房間的敘述列給使用者看，格式如下。

   ```
   房間名稱（檔名）
   來源：舊資料（全文引用）／新寫／舊資料＋補寫
   出口：north 〇〇；指令：enter 〇〇
   敘述：
   （完整文字）
   ```
4. **使用者確認後**才建立房間檔案；有修改意見就先改清單。
5. 製作完成後把最終敘述與設計重點寫進 `docs/AREA_<區域>.md`，與程式一起提交。

沒有完整敘述的房間一律由 Claude 撰寫，不必另外請使用者補。

## 三、敘述長度與版面

- 自行撰寫的敘述，在遊戲畫面上**至少三行、最多四行**，**最後一行至少六個字**。
- 遊戲每行寬 70（中文字算 2），第一行前面空四格。換算下來，全形字數：
  - 三行：**74～103 字**
  - 四行：**109～138 字**
- 敘述寫成**一整段**，由遊戲的 look 自己縮排換行，不手動斷行。
- **不受長度限制**：全文引用的舊資料、設計表上的原文。

## 四、敘述的內容

### 1. 不寫單純指路的句子

出口那一行已經列出方向，所以不要寫「往西則是西大街」「往南可以回到東大街」「街道往東西兩頭延伸」。
錢莊、藥鋪、書肆、城門這類特殊建築可以寫進敘述，但要帶出它的樣子，不要只是指向某個房間。
例如「南邊是一間氣派的錢莊」，再補上門面、招牌、人來人往的情形。

### 2. 不用括號提示指令或方向

不寫「（climb 石頭）」「(暗巷)」「(out)」。要讓玩家知道能怎麼走，就把線索寫進景物裡。
例如「石面上有幾處被踩出來的凹痕，看起來可以攀爬上去」。
`tests/test_area_oldpine.py` 會檢查這點。

### 3. 不提等級數字、不提指令

玩家看得到的文字不寫「幾級」，也不寫 `powerup`、`exert` 這類指令。用江湖說法與武功、狀態的名稱。
（來源：`CLAUDE.md` 的「遊戲內文字」。）

### 4. 特殊出口與探索指令要有線索

設計需求要求有特殊出口、探索指令（`enter`、`climb`、`pass`、`swim`、`cave` 等）時，
敘述裡要有**看得出來的景物線索**，讓細心的玩家能推得出來，但不直接說出指令。
指令本身只記在區域文件，不寫進遊戲敘述。

## 五、文筆：寫景，不寫招式

房間敘述的語境參考使用者提供的武俠小說（金庸、古龍、梁羽生、黃易等），學它**寫景、寫人、寫氣氛**的語境。
`docs/martial_arts/武俠敘述風格指南.md` 是打鬥用的，**不要把對打的招式寫法套進房間敘述**：
不用「起勢→出手→去向」骨架，不用 `$N`、`$n`、`$l`，也不用兵器動詞堆砌畫面。

寫景的做法（自撰歸納，不抄小說原句）：

- **由遠到近、由大到小**：先寫整體的天色、地勢、氣味、聲響，再落到眼前一兩樣具體的東西。
- **用感官帶氣氛**：不只寫看到的，也寫聽到、聞到、冷熱。一間房間至少有一種非視覺的感受。
- **一兩個細節就夠**：與其羅列，不如挑一個有故事的細節，例如磨得發亮的門檻、牆角積塵的兵器架。
- **人跡暗示江湖**：酒旗、馬蹄印、佩刀的過客、斑駁的告示。不必明講「這裡很危險」，讓景物自己說。
- **語氣含蓄**：多用「隱約」「依稀」「看來」「想必」，少用驚嘆與形容詞疊加。
- **句子有長短**：長句鋪景，短句收尾，最後一行落在一個能讓人停一下的畫面。
- **同一區域的房間要有各自的樣子**：同一條街的相鄰房間，不要重複同樣的開頭與句型。
- **避免**：現代用語、遊戲術語、直接提示任務、與相鄰房間矛盾的景物。

小說文本若之後再提供，歸納到這份文件的本章，不放原文進專案。

## 六、出口與功能

- 一般方向出口列在 exits。
- 要用指令進出的地方不列在 exits，要寫進區域文件的「指令出入」。
- 尚未製作的區域，只在敘述中帶過，暫不開出口。
- **安全區**（不能戰鬥）：客棧、當鋪、廟宇、渡口等，依設計表標示。
- **功能房間**：當鋪 `HOCKSHOP`、錢莊 `BANK`、旅館 `INN`（存檔點）。
- **官兵**：一律用 `obj/area/garrison.c`（不攔人的通用版）。雪亭鎮那組只攔雪亭鎮山路。
- **商店**：賣的武器一律是普通品，不帶隨機附加屬性（見 `WEAPON_AFFIX.md`）。

## 七、網頁地圖屬性

依 `docs/MAP_RUNTIME_CONTRACT.md`，房間可選填：

- `map/area`：區域名稱，例如 `老松林`。
- `map/layer`：圖層，例如 `地面`、`洞穴`、`樹上`、`二樓`。
- `map/mode`：設為 `maze` 時，沒走過的目的地顯示 `？？？`。

沒設定的房間視為一般地面層。洞穴、樓上、樹上、迷宮都要設定圖層，否則地圖會畫錯。

## 八、驗證與文件

- 實際載入遊戲，走過所有出口與指令出入，用 `look` 看過每間房間的版面。
- 加測試（參考 `tests/test_area_qiaoyin.py`、`tests/test_area_oldpine.py`）：行數、最後一行字數、括號提示、出口互通。
- 區域文件放 `docs/AREA_<區域>.md`，內容包含房間清單、指令出入、安全區、功能、NPC、驗證結果。
- 文件與程式一起提交、一起開 PR；開 PR 的做法見 `CLAUDE.md`。

- [ ] 沒有完整敘述的房間已寫好，並在製作前列給使用者確認
- [ ] 自寫敘述三～四行、字數落在範圍內、最後一行至少六個字
